# 每轮任务日志规范

## 1. 目的

保证每轮实施结束后，都能回答下面几个问题：

- 这一轮做了什么
- 做到了什么程度
- 测了什么
- 有没有 bug
- 下一轮该接着做什么

## 2. 日志归档建议

建议目录：

`docs/implementation/logs/<phase>/`

建议文件命名：

`YYYY-MM-DD-round-<n>.md`

示例：

`docs/implementation/logs/phase-0/2026-04-21-round-01.md`

## 3. 每轮日志必须包含的内容

- 轮次编号
- 所属阶段
- 本轮目标
- 实际完成项
- 未完成项
- 变更文件
- 测试项目
- 测试结果
- 新发现 bug
- 已修复 bug
- 遗留风险
- 下一轮建议

## 4. 什么时候必须写日志

- 每一轮任务结束时
- 每一轮阶段性验证结束时
- 每一次准备切到下一阶段前

## 5. 什么情况下不能跳过日志

- 改了代码
- 改了配置
- 跑了测试
- 发现了 bug
- 形成了阶段结论

## 6. 日志质量要求

- 不写空泛表述
- 结果必须和测试挂钩
- bug 必须写清复现条件或影响范围
- 下一轮建议必须是可执行动作
