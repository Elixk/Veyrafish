# Veyrafish 前端重构总规划

## 1. 先说结论

现在不应该直接按效果图重写整站，而应该先做一轮“结构性前端重构”。

这轮重构的目标不是“最像图”，而是：

- 先让页面层级正确
- 先让功能位置合理
- 先让首页像产品首页，而不是像开发控制台

## 2. 为什么不能直接照着效果图写

## 2.1 效果图解决的是视觉，不是结构

你给的参考图已经把风格立住了，但这些图默认有几个前提：

- 五个引擎已经是独立页面
- 数据结构已经适配卡片、图表和摘要区
- 系统运维按钮已经从用户主界面移走

而当前仓库还没有满足这些前提。

## 2.2 当前前端最大的难点不在 CSS，而在职责错位

当前 `templates/index.html` 把：

- 分析输入
- 配置管理
- 系统启动
- 控制台输出
- 论坛展示
- 报告生成

全部堆在同一层页面中。

如果直接套高保真视觉，最后只会变成“好看的控制台”，不会变成真正可用的产品前端。

## 3. 推荐的前端重构路线

## Round A：功能收敛与页面拆分

目标：

- 明确顶层导航
- 把五个引擎从标签切换升级为页面视图
- 把系统控制从首页拆走

本轮重点：

- 不追求重视觉
- 只修结构

## Round B：总览页重构

目标：

- 完成新首页
- 让首页承担“输入 + 总览 + 快速跳转”

本轮重点：

- 主输入区
- 五引擎摘要卡
- 最近任务 / 最近报告
- 顶部导航与系统工具区

## Round C：报告页优先重构

目标：

- 先把 Report 页做成最完整的内页

原因：

- 当前 Report 模块功能最完整
- 最容易形成“产品感”
- 最容易和导出能力形成闭环

## Round D：洞察 / 媒析 / 检索 / 论坛逐个落地

目标：

- 按信息密度从高到低逐页重构

建议顺序：

1. Report
2. Insight
3. Query
4. Media
5. Forum

## Round E：高保真视觉增强

目标：

- 在结构稳定后，再逐步贴近参考图风格

包含内容：

- 纸纹背景
- 印章元素
- 墨色层级
- 国风字体体系
- 山水装饰

## 4. 第一轮重构必须做的事

1. 整理当前所有功能键并建立页面归属。
2. 决定哪些功能属于首页，哪些属于引擎页，哪些属于系统层。
3. 把“顶部导航 + 页面主工作区 + 系统工具区”的框架定下来。
4. 先做低视觉风险版线框结构。

## 5. 第一轮重构不应该先做的事

1. 不要先写复杂 SVG 水墨动效。
2. 不要先做书法字体大面积混排。
3. 不要先把所有内页都做成高保真。
4. 不要先把管理员功能继续放在首页显眼位置。

## 6. 视觉实现策略

建议分三层：

- `L1`: 黑白灰 + 朱砂点缀 + 纸纹背景
- `L2`: 国风边框、题签、印章、山水装饰
- `L3`: 动态墨滴、远山视差、复杂动效

这意味着：

- 第一轮只做 `L1`
- 第二轮再进 `L2`
- 确认性能和结构稳定后再试 `L3`

## 7. 当前最适合的前端第一步

如果你下一步就要我开始写代码，我建议不是直接重画整页，而是：

### Step 1

先把 `templates/index.html` 的现有功能按模块拆成：

- 顶部导航
- 首页总览
- 系统工具面板
- 五个页面容器

### Step 2

先完成新的首页线框结构

### Step 3

先完成 Report 页线框结构

这样做的好处是：

- 你能快速看到产品结构是否顺
- 后续视觉增强不会把功能打散
- 复杂效果可以最后再叠加

## 8. 本轮规划结论

这次前端规划的核心结论只有一句：

**Veyrafish 前端下一步要先重构“信息架构”，再重构“视觉表达”；先让它像一个产品，再让它像效果图。**
