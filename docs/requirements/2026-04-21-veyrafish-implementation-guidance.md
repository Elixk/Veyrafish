# Veyrafish 分阶段实施指导需求冻结

日期：2026-04-21
运行模式：`/vibe`
主题：将升级方向文档落成总实施清单、阶段实施清单与日志规范

## 1. Goal

基于已有升级方向，产出一套可执行的实施指导文档体系，能够直接指导后续分阶段升级。

## 2. Deliverables

本轮至少产出以下文档：

- 总实施清单
- 分阶段实施清单
- 每阶段的验收与测试指导
- 每轮任务结束后的日志模板与归档规范

## 3. Constraints

- 文档必须以当前仓库结构为前提，不写脱离项目现实的流程
- 每个阶段都必须明确目标、任务、产出、测试、bug 排查、日志要求
- 总清单与分阶段清单之间不能冲突
- 只新增文档，不修改业务代码

## 4. Acceptance Criteria

- 能从总清单直接跳到每个阶段的独立清单
- 每个阶段都定义“开始条件 / 完成条件 / 交付物 / 测试 / bug 检查 / 日志”
- 文档可以直接用于拆任务、执行和阶段复盘
- 对“每轮任务结束后记日志”的要求有统一模板

## 5. Non-goals

- 本轮不直接执行升级代码改造
- 本轮不补装依赖
- 本轮不跑完整系统验证

## 6. Delivery Truth Contract

- 以 [UPGRADE_DIRECTIONS.md](d:/user/landx/Desktop/computer%20design%20competition/Veyrafish-main/UPGRADE_DIRECTIONS.md) 作为上游方向依据
- 当前文档体系面向“后续实施”，不是伪装成已经完成升级
