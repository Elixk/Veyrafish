## 1. Goal

将 Veyrafish 当前前端从“能跑的工程控制台”升级为“维舆 / Veyrafish 新中式水墨风工作台”，同时保留系统真实运行能力。

本阶段不追求一次性把所有参考图里的复杂数据能力都接真实后端，而是先完成：

1. 品牌统一为 `维舆 / Veyrafish / 维舆-新时代高效通用多维度舆论平台`。
2. 全局视觉底座统一：水墨背景、朱砂印章、宣纸卡片、竹子/小舟/山水素材。
3. 在不破坏现有功能的前提下重构六个模板页面。
4. 对 KPI、图表、排行、矩阵等展示组件先做演示态，并评估后续真实数据接入难度。

## 4. Constraints

- 不引入前端构建链路，继续保持 Flask 模板 + 静态 CSS/JS 的方式。
- 不重写后端业务接口，不改变既有 API 路径和参数。
- 不破坏现有 `id`、事件绑定、Socket、SSE、iframe、报告导出链路。
- 不把参考图里的所有复杂组件都误当成第一轮真实功能。
- 不在本轮接入复杂图表库新依赖；如使用图表，优先 CSS/SVG 静态演示或轻量占位。
- 不让水墨装饰遮挡文本、按钮、日志、报告预览等真实工作区。

## 5. Acceptance Criteria

### 5.1 视觉层

- 六页不再残留旧品牌文案作为对外品牌。
- Header、Footer、背景、水墨素材和按钮风格统一。
- 页面主体接近参考图的布局气质，但不牺牲真实操作入口。
- 文本不重叠、不溢出按钮或卡片。

### 5.2 功能层

- 系统配置弹窗仍可打开、保存、保存并启动。
- 系统启动、状态轮询、关闭确认、Socket 状态不回归。
- 总览页仍可输入议题、上传模板、启动分析、进入各引擎。
- 引擎页仍可显示 iframe 或未运行占位态。
- Forum 页仍可实时/轮询显示讨论消息。
- Report 页仍可生成报告、查看进度、预览并导出 HTML/PDF/MD。

### 5.3 产品层

- 第一屏能体现“维舆”的品牌识别、水墨气质和多引擎工作台定位。
- 演示数据组件能解释系统能力，但不伪装成已经完全接入真实后端。
- 后续可以根据 AI 输出结构，逐步把 KPI、图表和矩阵接入真实数据。

## 6. Data Visualization Difficulty Assessment

| 组件类型 | 第一轮策略 | 后续真实接入难度 | 说明 |
|---|---|---|---|
| KPI 指标 | 静态/半静态演示 | 中 | 需要从 task/evidence/report 中抽取统一统计字段 |
| 趋势折线 | 静态 SVG/CSS 或固定数据 | 中高 | 当前 AI 输出偏文本，需要沉淀时间序列 schema |
| 排行榜 | 演示数据 | 中 | 可从 evidence source、Forum message、engine logs 归并 |
| 情绪分布 | 演示数据 | 中 | `sentiment_analysis` 已硬化，但还需批量输入与聚合层 |
| 风险矩阵 | 演示数据 | 高 | 需要定义风险分、情绪分、讨论量的计算规则 |
| Forum 阵营图 | 演示数据 + 真实消息流并存 | 高 | 需要观点聚类/阵营分类，不适合第一轮强接 |
| Report 纸张预览 | 真实报告优先，演示空态补足 | 中 | 现有 ReportEngine 已有导出链路，主要是视觉包装 |

## 7. Manual Spot Checks

- 打开 `/`，能看到 `维舆` 品牌、水墨素材、输入区、五引擎入口。
- 点击系统配置，弹窗正常出现并能读取 `.env`。
- 点击保存并启动系统，仍走 `/api/system/start`。
- 打开 `/forum`，实时消息流、刷新消息、清空视图仍可用。
- 打开 `/report`，生成最终报告、任务进度、下载按钮仍可用。
- 切换 `/insight`、`/media`、`/query`，iframe 占位与状态显示仍正常。

## 8. Non-goals

- 不在第一轮完成所有图表真实数据接入。
- 不重构为 React/Vue 或引入构建工具。
- 不修改核心后端分析流程。
- 不在本轮做 Docker 部署。
- 不将参考 HTML 原样覆盖真实模板。
