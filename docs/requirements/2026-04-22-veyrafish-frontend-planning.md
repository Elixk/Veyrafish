# Veyrafish 前端规划需求冻结

日期：2026-04-22
运行模式：`/vibe`
主题：基于现有前端与设计参考，先冻结前端功能边界、页面信息架构和重构路线

## 1. Goal

在不直接启动高难度 UI 全量重写的前提下，先完成 Veyrafish 前端规划，明确：

- 当前前端实际有哪些功能键和页面职责
- 哪些功能必须保留，哪些应该迁移位置，哪些应降级到二期
- 总览页与五个引擎页的页面分层应该是什么
- 如何从当前单页控制台壳，渐进式重构到新的前端结构

## 2. Deliverables

本轮至少产出：

- 一份前端重构总规划
- 一份现有前端功能清单
- 一份页面信息架构文档
- 一份本轮阶段日志

## 3. Constraints

- 当前目标是规划，不是直接实现高保真视觉
- 必须以真实的 `templates/index.html` 为基础识别功能
- 设计参考只作为视觉方向，不应直接当实现需求
- 重构路线必须考虑现有后端 API 和运行方式
- 每轮任务结束后需要写日志

## 4. Acceptance Criteria

- 列清当前前端所有关键功能键和功能分组
- 明确首页、五个引擎页、系统控制层的职责边界
- 给出功能优先级和渐进式重构路线
- 对“效果图好看但实现过重”的部分给出降级实现策略
- 明确前端第一轮重构应该先做什么，不应该先做什么

## 5. Manual Spot Checks

- 检查当前首页是否同时承担搜索、控制台、论坛、报告、系统管理职责
- 检查现有按钮是否混合了产品操作与系统运维操作
- 检查报告页是否已经具备独立子界面雏形
- 检查参考效果图中哪些区域是视觉层，哪些区域其实需要真实数据结构支撑

## 6. Non-goals

- 本轮不直接改造 `templates/index.html`
- 本轮不直接切前后端分离
- 本轮不直接实现国风高保真内页

## 7. Delivery Truth Contract

- 结论以 `templates/index.html` 当前真实功能为准
