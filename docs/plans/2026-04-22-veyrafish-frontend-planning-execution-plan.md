# Veyrafish 前端规划执行计划

日期：2026-04-22
运行模式：`/vibe`
内部执行等级：`L`

## 1. Strategy

优先做前端信息架构与功能收敛，不直接进入高保真实现。先把“功能键、页面职责、层级关系、渐进式路线”冻结，再进入真正的 UI 重构。

## 2. Waves

### Wave 1：现状抽样

- 阅读现有 `templates/index.html`
- 抽取主要按钮、交互入口、页面容器与控制逻辑
- 识别当前前端实际上承担的产品功能与系统功能

### Wave 2：参考资料抽样

- 阅读对话导出的高保真说明
- 阅读参考 JSX 文件，确认视觉语言
- 抽样查看首页与内页效果图

### Wave 3：功能清单冻结

- 列出当前功能键
- 标记必须保留、迁移、合并、延后项

### Wave 4：页面架构冻结

- 定义总览页
- 定义洞察、媒析、检索、论坛、报告五个引擎页
- 定义系统控制层的放置方式

### Wave 5：重构路线输出

- 明确第一轮前端重构目标
- 明确哪些视觉效果不应该优先实现
- 写入本轮日志与治理收据

## 3. Ownership Boundaries

- 本轮仅新增规划文档和日志
- 不修改前端实现
- 不调整后端接口

## 4. Verification

通过以下方式验证：

- 当前前端功能是否被完整盘点
- 页面分层是否覆盖首页、五引擎页和系统控制层
- 重构路线是否区分 MVP、增强版和高保真阶段

## 5. Cleanup Expectations

- 写入运行收据
- 写入 Phase 3 本轮日志
- 不保留临时文件
